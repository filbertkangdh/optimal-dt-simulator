Delivery-time → GMV simulator

This is a DT → GMV simulator: explore the impact on GMV if we improve or worsen delivery time (DT). Pick a country and a base (actual) DT scenario to see how logistics operating metrics move, then set a target DT to see the GMV impact vs. today's baseline. Sessions and AOV are Q2’2026 inputs; the underlying model is trained on H2’2025–H1’2026 data.

Overall GMV Impacts

Everything above, stitched together into a P&L: the same DT scenario (base→target DT) and OL scenario (base→target OL) driving every section on this page. Total GMV = GMV from CVR + GMV from Fail Recovery (Order Late) — defect cost is NOT a GMV lever here, it's a real cost, lumped together with Rider Cost into Total Cost instead. Revenue = Total GMV × take rate%; Gross Profit = Revenue − Total Cost. Two optimization functions: Gross Profit ROI = ΔGross Profit/ΔTotal Cost (a same-period ratio, no reorder-retention); Optimal DT = Gross Profit + Total CLTV, a dollar sum that folds in the reorder-retention channel's lifetime value (Gross Profit per on-time/late band × Customer Lifetime in months, 1/(1−day-30 reorder rate)). GMV ROI (ΔGMV/ΔTotal Cost) is also shown for context but is no longer what either optimization function searches for.

DT → Revenue, Cost & optimization functions

4 figures, all against candidate Target DT across this country’s own observed DT range, holding Base DT fixed at today’s scenario: Total Revenue and Total Cost (levels), then the 2 optimization functions’ own values (Gross Profit ROI, Gross Profit + Total CLTV). “Find best ROI DT” sets Target DT to whichever function is selected above the sliders, but the Best-DT marker on the Gross Profit ROI / Optimal DT charts below always reflects THAT chart’s own function, regardless of which one is currently selected. Under Gross Profit ROI, candidates with negative ΔGMV are excluded from the search (a slower/GMV-losing target DT can make this ratio look numerically "better" purely by dividing two negative numbers — see the P&L table’s caveat above) — so that chart’s marked Best DT may sit BELOW its own visual maximum if that maximum falls in a negative-ΔGMV region; the full curve is still plotted for transparency.

On-time GMV retention uplift — target DT vs. base DT

A different channel from Part B below: even orders that are ALREADY on-time reorder somewhat better when DT gets faster still. On-time's SHARE of orders is held fixed at the base-DT scenario here (Part B's mix-shift math handles the share moving, so this stays isolated to just the rate effect, not double-counted) — only the RATE moves, via a non-parametric day-level bucket-and-average of on-time orders' own DT (2025-07-01–2026-06-30, censoring-guarded), not a fitted regression. Part B
Reorder-rate GMV impact of order-late (10-20/20-30/>30min) orders

Extended 2026-07-28 from the >30min band alone to all 3 late bands. OL10-20 and OL20-30's SHARE of orders is predicted directly from the DT scenario above via the peer's own pct_late_10_20/pct_late_20_30 curves -- no separate control, same mechanism as the logistics metrics above. OL>30's share instead comes from the Target OL basis toggle in the main panel at the top (predicted from target DT, optionally reduced further, or set manually). On-time = the complement of all 3 late shares. This translates each band's SHARE change into a downstream reorder-GMV effect (“GMV Retained”) using real Kaplan-Meier reorder-survival curves fit per band (2025-07-01–2026-07-23) -- each band's own reorder rate stays fixed, only the mix moves.

Fail rate & delay-related defect cost impact

Same OL scenario as above (base OL → target OL), but a different downstream effect: the peer's own OL→fail-rate and OL→defect-rate curves (fit directly against OL, not DT) at those two OL values. Defect cost = defect rate × gross orders ex ODR (Q2’2026 avg monthly total orders, primary brand entity only, excluding the separate ODR entity) × €1.80/defect — a flat unit-cost assumption, not the peer's own defect-rate→defect-cost curve.

Methodology & known limitations
  • GMV formula and methodology (updated 2026-07-23). GMV is derived as predicted CVR × orders-per-conversion × AOV × (1 − predicted fail rate). CVR is now modeled at zone-day grain (each country's model is fit on that country's zones' daily rows together, with a zone fixed effect, then collapsed to a single country-level curve by session-weighting across zones — i.e. "this country's typical zone, weighted by where volume actually is"): CVR ~ intercept(zone‑adjusted) + PDT + PDT² + healthy_vendor_availability_pct + mean_delay + surge_multiplier + is_special_day, evaluated at is_special_day = 0 (a typical, non-special day) for this simulator. This replaces the earlier country-day CVR spec (surge_by_time_pct, shrink_pct, close_pct, avg_delivery_distance_km are no longer CVR inputs — their mini-charts above remain as DT→mediator context only). Based on the base (actual) DT: PDT and mean_delay are still predicted via the peer's DT-mediator curves; surge_multiplier is predicted via this project's own DT→surge_multiplier curve (log-linear, per country, fit directly from this project's own data since the peer's file never modeled this metric — see its own confidence badge on the "Surge multiplier" card above, labeled "this project's own DT curve" to distinguish it from the peer-sourced curves); healthy_vendor_ availability_pct stays held fixed, at each country's Q2’2026 (Apr–Jun) session-weighted mean from the zone-day panel. Special days are FLAGGED in training (not dropped, ~8% of rows) rather than excluded.
  • Not a causal model. Both the logistics metrics model and this project's CVR model are fitted associations from observational data, not identified causal effects — treat every number here as descriptive, not a guaranteed outcome.
  • Delivery CPO formula and methodology. Delivery CPO = EPH ÷ predicted UTR(DT). UTR (orders per rider-hour) is DT-predicted using the exact same peer curve as the “Utilization rate (UTR)” card in the metrics grid above — no separate model. EPH (€/rider-hour) is a user input, defaulting to that country's Q2’2026 (Apr–Jun) CPH from eph_eur.csv, matching the same Q2’2026 baseline window used for sessions/AOV/DT elsewhere in this tool — editable to test other rider-cost assumptions. Since eph_eur.csv is monthly-grain only (no quarterly row), Q2’s 3 months are combined as an hours-weighted average, not a plain mean: each month's rider-hours are derived as successful orders ÷ UTR (since UTR is defined as orders per rider-hour), then EPH = ∑(CPH × hours) ÷ ∑(hours) across Apr–Jun — the correct way to combine an hourly RATE over unequal exposure, as opposed to averaging the 3 monthly rates directly. Total rider cost = Delivery CPO × Q2’2026 avg monthly (successful) orders (that quarter's total orders ÷ 3, matching how avg monthly sessions is computed for the GMV formula), with that order volume held FIXED across base and target DT (same fixed-volume approach as the GMV formula holding sessions fixed) — this isolates the cost-per-order effect of the DT scenario itself, not a change in order volume. Target EPH adjustment (2026-08-04). EPH is no longer held constant across base and target — a ±20% “Target EPH adjustment” slider lets Target-DT's EPH move independently of Base-DT's, e.g. to test a rider-pay change bundled with the DT scenario. Target EPH = Base EPH × (1 + slider%); Delivery CPO becomes Base CPO = Base EPH ÷ UTR(baseDt), Target CPO = Target EPH ÷ UTR(targetDt). At the slider's default of 0% this collapses back to the original EPH-held-fixed behavior.
  • Turkey. Peer's coefficient file added Turkey coverage 2026-07-21 (as group_id 'tr' in that file, remapped to this project's own 't3' country code) — Turkey is no longer excluded from the country picker. Taiwan still has no country-level curves in peer's file at all (population-fallback numbers for Taiwan would be misleading, not just less precise) — removed from the data bundle entirely (2026-07-30), not just hidden from the picker.
  • GMV ROI impact (updated 2026-07-30). Decomposed into two absolute-level ratios, each annual GMV ÷ monthly rider cost at that state: GMV ROI Base (annual GMV at base DT ÷ monthly rider cost at base DT) and GMV ROI Target (annual GMV at target DT, INCLUDING the OL fail-rate and defect-rate components ÷ monthly rider cost at target DT). The headline GMV ROI impact figure is GMV ROI Target − GMV ROI Base — a difference of two levels, NOT the old delta-uplift/delta-cost ratio (that earlier definition is superseded; don't compare the two numbers directly). Sign still depends on both levels, so it's intentionally not color-coded good/bad — always read it together with the Base/Target ratios shown underneath. “Find best ROI DT” (below) now searches for the target DT that maximizes GMV ROI Target itself, not the old ratio.
  • Overall GMV Impacts (2026-07-24). Overall GMV uplift = component 1 (GMV uplift from Reduced DT, the existing DT→CVR→GMV chain, which already has its OWN DT-based fail-rate factor baked in) + component 2 (GMV uplift from the OL-fitted fail-rate curve specifically, isolated at the target-DT CVR so it adds to component 1 without re-counting the DT-based fail-rate effect already inside it) + component 3 (GMV uplift from reduced defect rate, OL — this is the defect-COST-avoided figure reframed as a GMV-equivalent value and summed into the total per explicit user request; it is a cost-avoidance figure, not literal incremental revenue). GMV Retained (day 30, from Part B) is shown separately below the breakdown — a different downstream reorder-cohort revenue channel, NOT summed into the total. Superseded 2026-08-01, see below.
  • GMV ROI impact reworked (2026-08-01, per user + boss's direction) — supersedes the two entries above. Defect cost is no longer a GMV lever: it's a real cost, moved out of the GMV numerator and lumped together with rider cost into one Total Cost denominator (Total Cost = Rider Cost + Defect Cost). GMV (numerator) is now just 2 levers: reduced DT + reduced fail rate (OL). The headline GMV ROI impact card, and the GMV ROI impact — Retained GMV + Total GMV uplift card, both now use the standard incremental ROI % formula instead of the base/target-level ratio design: Incremental ROI % = (ΔFinancial Margin − ΔCost) / ΔCost × 100, where ΔFinancial Margin = ΔGMV × Take Rate% (30%, hardcoded) and ΔCost = Total Cost Target − Total Cost Base. No abs() on the denominator — a negative ΔCost (cost going down, otherwise favorable) can flip the % negative even in a genuinely good scenario; read the ΔMargin/ΔCost figures alongside the %, not the % alone. The GMV ROI impact — Retained GMV only card is REMOVED. The old base/target-level "X ratio" fields are still computed internally (unchanged) so “Find best ROI DT” and its 3-way lever toggle keep working exactly as before — they're just no longer shown on these 2 cards.
  • Headline GMV ROI impact reworked to a plain ΔGMV/ΔCost ratio (2026-08-03, per user). The headline GMV ROI impact card (only — the GMV ROI impact — Retained GMV + Total GMV uplift card below keeps the Incremental ROI % formula from the entry above) now shows gmvRoiDeltaRatio = (GMV Target − GMV Base) / (Total Cost Target − Total Cost Base) = ΔGMV / ΔCost directly as an "X.XXx" ratio — literally the same 2 numbers already shown in the GMV (numerator)/Total Cost (denominator) sub-rows below, divided by each other. No take rate applied (unlike the Incremental ROI % formula above), no annualizing needed (annualizing both sides by the same ×12 factor cancels in a ratio). Superseded, within the same session, an earlier same-day attempt (roiTarget: annual GMV at target DT ÷ monthly Total Cost at target DT, a base/target-LEVEL ratio) that mismatched annual-vs-monthly units and didn't reconcile with the visible sub-rows — don't revert to that. "Find best ROI DT"'s Instantaneous lens and the new "DT → GMV ROI curve" section below were also switched (same day, per user) to maximize this same gmvRoiDeltaRatio, so the headline card and the optimizer/curve agree — roiTarget/roiBase (the old level ratio) are still computed but no longer used by the Instantaneous lens; Long Term/Combined are unchanged, still base/target-LEVEL ratios. Instantaneous's singularity is now at ΔCost≈0, which by construction sits exactly at Target DT == Base DT — the existing relative-floor guard (vs. baseline monthly rider cost) naturally excludes a neighborhood around Base DT for this lens without needing a separate guard band; see ROI_OPTIMIZE_MODES.instant .singularityCheck.
  • N-shape (hump) GMV flattening (2026-08-03, per user). For any country whose predicted GMV curve has a genuine interior peak within its own OBSERVED DT range, the CVR/GMV pathway (predictCVR) is now flattened at the peak for every DT below it — there is no causal evidence that reducing DT that far actually improves CVR (the decline is more likely a demand-simultaneity artifact, same diagnosis as this project's Thread-1 hump findings). Applies symmetrically to Base and Target DT, auto-detected per country (not a hand-picked list). predictFailRate is untouched and keeps moving with the raw DT — any residual GMV movement below a country's peak now comes purely from fail-rate improvement. 10 of 15 visible countries have a genuine interior peak; materially changes those countries' headline ΔGMV numbers versus any pre-2026-08-03 screenshot or export (intended, not a bug).
  • EU event-mix CVR recovery below the peak (2026-08-21, per user). For the 4 countries in "EU CVR Impact Coefficient.csv" (Czech Republic/Hungary/Norway/Sweden), the flat freeze above is replaced by a real, event-mix-explained recovery: each of 3 operational events (vendor closures/stock shrink/surge, already DT-predicted via pct_close/pct_shrink/pct_surge_by_time) contributes its own predicted-rate reduction below the peak times that event's own CVR penalty (the sheet's per-country, per-event figure), anchored so the curve stays continuous with the raw curve at the peak. Every other country still assumes zero CVR improvement below its peak as before.
  • "Find best ROI DT" (Instantaneous) negative-ΔGMV guard (2026-08-03, per user). The ΔGMV/ΔCost ratio above can be numerically HIGHEST in the region where BOTH ΔGMV and ΔCost are negative (a slower target DT that loses GMV but saves more on rider cost) — dividing two negatives looks positive and gets larger the WORSE the GMV loss is. ROI_OPTIMIZE_MODES.instant.isValidCandidate now excludes any candidate with totalGmvUplift < 0 from the search, so "best DT" can never be a deliberately GMV-losing recommendation. Long Term/Combined lenses are unaffected. The curve chart still plots the full raw ratio (including the now-excluded region) for transparency — the marked "best" point can sit below the curve's own visual peak.
  • Whole-minute DT everywhere (2026-08-03, per user: "simplify, DT ranges are all in absolute [whole] numbers"). Every DT input (Base/Target sliders and number boxes), chart grid (DT_GRID, the GMV/metrics/surge/UTR/rider-cost charts), search (findBestRoiDt, the N-shape peak search, the ROI curve), and displayed DT value now uses whole minutes only (was 0.05–0.5min resolution depending on the code path). A country's observed DT range is rounded IN to the tightest whole-minute range containing real data (observedRangeWhole: ceil the min up, floor the max down) so every whole-minute DT the UI can ever be set to is backed by actual observed data. Default Base DT on country select is now Math.round(dtMean) (was 1-decimal). Purely a simplification of inputs/search/display resolution — the underlying curves (evalCurve, the logistic z-score transform, etc.) are untouched and still fit on the original continuous data.
