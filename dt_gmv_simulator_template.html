Delivery-time → GMV simulator

This is a DT → GMV simulator: explore the impact on GMV if we improve or worsen delivery time (DT). Pick a country and a base (actual) DT scenario to see how logistics operating metrics move, then set a target DT to see the GMV impact vs. today's baseline. Sessions and AOV are Q2’2026 inputs; the underlying model is trained on H2’2025–H1’2026 data.

Same OL scenario as above (base OL → target OL), but a different downstream effect: the peer's own OL→fail-rate and OL→defect-rate curves (fit directly against OL, not DT) at those two OL values. Overall GMV Impacts

Everything above, stitched together: the same DT scenario (base→ target DT) and OL scenario (base→target OL) driving every section on this page, consolidated into one annual view. Overall GMV uplift = 1) GMV uplift from Reduced DT + 2) GMV uplift from reduced fail rate (OL) + 3) GMV uplift from reduced defect rate (OL) — component 3 folds in a cost-avoidance figure (defect cost) as a GMV-equivalent value, not literal incremental revenue. GMV retained from reorder rate (Part B) is a separate downstream revenue channel, shown below but NOT summed into the total.

Methodology & known limitations
  • GMV formula and methodology (updated 2026-07-23). GMV is derived as predicted CVR × orders-per-conversion × AOV × (1 − predicted fail rate). CVR is now modeled at zone-day grain (each country's model is fit on that country's zones' daily rows together, with a zone fixed effect, then collapsed to a single country-level curve by session-weighting across zones — i.e. "this country's typical zone, weighted by where volume actually is"): CVR ~ intercept(zone‑adjusted) + PDT + PDT² + healthy_vendor_availability_pct + mean_delay + surge_multiplier + is_special_day, evaluated at is_special_day = 0 (a typical, non-special day) for this simulator. This replaces the earlier country-day CVR spec (surge_by_time_pct, shrink_pct, close_pct, avg_delivery_distance_km are no longer CVR inputs — their mini-charts above remain as DT→mediator context only). Based on the base (actual) DT: PDT and mean_delay are still predicted via the peer's DT-mediator curves; surge_multiplier is predicted via this project's own DT→surge_multiplier curve (log-linear, per country, fit directly from this project's own data since the peer's file never modeled this metric — see its own confidence badge on the "Surge multiplier" card above, labeled "this project's own DT curve" to distinguish it from the peer-sourced curves); healthy_vendor_ availability_pct stays held fixed, at each country's Q2’2026 (Apr–Jun) session-weighted mean from the zone-day panel. Special days are FLAGGED in training (not dropped, ~8% of rows) rather than excluded.
  • Not a causal model. Both the logistics metrics model and this project's CVR model are fitted associations from observational data, not identified causal effects — treat every number here as descriptive, not a guaranteed outcome.
  • Delivery CPO formula and methodology. Delivery CPO = EPH ÷ predicted UTR(DT). UTR (orders per rider-hour) is DT-predicted using the exact same peer curve as the “Utilization rate (UTR)” card in the metrics grid above — no separate model. EPH (€/rider-hour) is a user input, defaulting to that country's Q2’2026 (Apr–Jun) CPH from eph_eur.csv, matching the same Q2’2026 baseline window used for sessions/AOV/DT elsewhere in this tool — editable to test other rider-cost assumptions. Since eph_eur.csv is monthly-grain only (no quarterly row), Q2’s 3 months are combined as an hours-weighted average, not a plain mean: each month's rider-hours are derived as successful orders ÷ UTR (since UTR is defined as orders per rider-hour), then EPH = ∑(CPH × hours) ÷ ∑(hours) across Apr–Jun — the correct way to combine an hourly RATE over unequal exposure, as opposed to averaging the 3 monthly rates directly. Total rider cost = Delivery CPO × Q2’2026 avg monthly (successful) orders (that quarter's total orders ÷ 3, matching how avg monthly sessions is computed for the GMV formula), with that order volume held FIXED across base and target DT (same fixed-volume approach as the GMV formula holding sessions fixed) — this isolates the cost-per-order effect of the DT scenario itself, not a change in order volume.
  • Turkey. Peer's coefficient file added Turkey coverage 2026-07-21 (as group_id 'tr' in that file, remapped to this project's own 't3' country code) — Turkey is no longer excluded from the country picker. Taiwan still has no country-level curves in peer's file at all and remains excluded (population-fallback numbers for Taiwan would be misleading, not just less precise).
  • GMV ROI impact. GMV annual uplift (Reduced DT + OL fail-rate improvement) ÷ rider cost delta (monthly), in the “Overall GMV Impacts” section below. This ratio's sign depends on BOTH the numerator and denominator's own signs — a scenario that raises GMV and lowers cost (the best case) produces the same negative sign as one that lowers GMV and raises cost (the worst case), so it is intentionally not color-coded good/bad. Always read it together with the GMV and rider cost deltas, not on its own.
  • Overall GMV Impacts (2026-07-24). Overall GMV uplift = component 1 (GMV uplift from Reduced DT, the existing DT→CVR→GMV chain, which already has its OWN DT-based fail-rate factor baked in) + component 2 (GMV uplift from the OL-fitted fail-rate curve specifically, isolated at the target-DT CVR so it adds to component 1 without re-counting the DT-based fail-rate effect already inside it) + component 3 (GMV uplift from reduced defect rate, OL — this is the defect-COST-avoided figure reframed as a GMV-equivalent value and summed into the total per explicit user request; it is a cost-avoidance figure, not literal incremental revenue). GMV Retained (day 30, from Part B) is shown separately below the breakdown — a different downstream reorder-cohort revenue channel, NOT summed into the total.
